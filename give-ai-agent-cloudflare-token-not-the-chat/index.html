Как дать AI-агенту токен Cloudflare и не показывать его в чате

Опубликовано 2026-11-19Обновлено 2026-11-19Данные Cloudflare проверены2026-11-19aicloudflare

Вы просите Claude Code добавить DNS-запись или задеплоить воркер, и он отвечает: нужен API-токен Cloudflare. Самое простое — скопировать токен из панели и вставить в чат. Агент сразу заработает, и именно поэтому так делают почти все.

Проблема в том, что чат никуда не девается. Переписка с агентом хранится на диске, с каждым сообщением целиком уходит провайдеру модели и оказывается у коллеги, которому вы скинули лог, чтобы он помог разобраться. Токен лежит там вместе со всем остальным.

Ниже — как мы устроили работу у себя: агент каждый день деплоит и правит зоны, а сам токен не видел ни разу. Документацию Cloudflare и Claude Code мы сверили 19 ноября 2026 года.

Если коротко, шагов четыре:

  1. Выпустите токен, который может только то, что нужно агенту.
  2. Положите его в файл, а передавать его инструментам поручите маленькому скрипту.
  3. Поставьте хук, который не даст агенту этот файл открыть.
  4. Свои токены кладите через буфер обмена, а не через чат.

Почему токен нельзя вставлять в чат

Вставить токен в сообщение — самый очевидный способ его засветить, но не единственный. Агент прочитает файл с ключами, если попросить его «посмотреть, что в .env», и всё содержимое файла окажется в переписке точно так же. Если у вас открыто два окна агента в двух проектах и одно передаёт другому ключ сообщением, ключ остаётся в истории обоих.

Есть и менее очевидный случай. В Claude Code можно набрать команду после !, и это выглядит как обычный терминал. Но документация прямо говорит, что такой режим “adds the command and its output to the conversation context”. Если написать токен в такой команде, он попадёт в переписку вместе со всем, что команда выведет.

Шаг 1. Выпустите токен с минимальными правами

Начните не с того, где хранить токен, а с того, что он умеет. Global API Key агенту не подходит совсем: сама Cloudflare пишет, что у него “has the exact same permissions as the user”, то есть он может всё, что можете вы. Без него не обойтись разве что при массовом добавлении зон, и это разобрано в статье про лимит зон. Для остальной работы агента нужен обычный API-токен с ограничениями.

В конструкторе токенов есть четыре настройки, которые стоит выставить. Первые две описаны на этой странице, ещё две — на странице об ограничении токенов.

Настройка Что пишет Cloudflare Что поставить агенту
Permissions “Choose the permissions to grant within the policy.” Только нужное задаче; чтение, если записи не требуется
Resources “specific accounts or zones” Только зоны, с которыми агент работает
Client IP Address Filtering “Once an Is in rule is applied, the token can only be used from the defined IP addresses.” Адреса вашего офиса или сервера в нотации CIDR
TTL “By default, tokens do not expire and are long lived.” Срок действия, равный сроку задачи

Одно право проверьте отдельно. Через API можно создавать новые токены, если у вас уже есть один: “you can create additional API tokens”. Отвечает за это право API Tokens Write, в списке прав оно описано так: “Grants write access to user’s API tokens”. Если такой токен утечёт, им можно выпустить новые, и отзыв старого уже ничего не решит. Агенту это право не нужно никогда.

Cloudflare показывает токен один раз (“The token secret is only shown once”), а новые токены начинаются с cfut_ — Cloudflare называет это “scannable format”, чтобы сканеры секретов могли найти токен в репозитории. Но переписку с агентом никакой сканер не читает. Если токен попал туда, остаётся только отозвать его и выпустить новый.

Шаг 2. Передавайте токен через скрипт, а не через агента

Положите токен в файл, который не попадает в git. У нас это .dev.vars, в других проектах чаще .env. Дальше нужен маленький скрипт: он читает файл и запускает нужную программу, например wrangler, передав ей токен через переменные окружения. Агент вызывает скрипт, wrangler получает токен, а в переписку попадает только результат работы. Этот блог деплоится именно так. Минимальная версия скрипта:

// with-token.mjs: node with-token.mjs <node script> [args...]
// Runs a Node script with the Cloudflare token from .dev.vars in its environment.
// Nothing from the file is printed; the token never appears on a command line.
import { spawnSync } from 'node:child_process';
import fs from 'node:fs';

const KEYS = ['CLOUDFLARE_API_TOKEN', 'CLOUDFLARE_ACCOUNT_ID'];
const env = { ...process.env };
for (const line of fs.readFileSync('.dev.vars', 'utf8').split(/\r?\n/)) {
  const eq = line.indexOf('=');
  const key = line.slice(0, eq).trim();
  const value = line.slice(eq + 1).trim().replace(/^(['"])(.*)\1$/, '$2'); // KEY="value" too
  if (eq > 0 && KEYS.includes(key)) env[key] = value;
}
const missing = KEYS.filter((k) => !env[k]);
if (missing.length) {
  console.error(`.dev.vars has no ${missing.join(', ')}`);
  process.exit(2);
}
const r = spawnSync(process.execPath, process.argv.slice(2), { stdio: 'inherit', env });
process.exit(r.status ?? 1);

Проверить можно так: попросите агента выполнить node with-token.mjs node_modules/wrangler/bin/wrangler.js whoami. Wrangler ответит, что он “logged in with an Account API Token”, взятым “from the CLOUDFLARE_API_TOKEN environment variable”, а самого токена в ответе не будет. Скрипт берёт из файла только две нужные переменные и запускает программу напрямую, без командной оболочки, так что токен не попадает и в историю команд.

Чтобы агент не забыл про скрипт, напишите об этом одной строкой в CLAUDE.md или AGENTS.md проекта: команды wrangler запускать через node with-token.mjs, файл с токеном не открывать.

Шаг 3. Запретите агенту открывать файл с токеном

Строка в инструкциях — это просьба. Агент может её забыть, особенно в длинной сессии, и однажды всё-таки выполнить cat .env, чтобы «проверить настройки». Поэтому нужен хук: Claude Code запускает хук PreToolUse перед каждым действием агента, и хук может это действие запретить. В Codex такие хуки тоже есть, только чужой хук он запустит после того, как вы подтвердите его в /hooks.

Наш хук смотрит, к какому файлу обращается агент и какую команду он запускает, и отказывает, если там встречается файл с секретами: .env и .env.* (кроме .env.example), .dev.vars, всё внутри папки .secrets, *.pem, id_rsa. Он лежит в открытом репозитории secret-handoff, в README есть готовые настройки для Claude Code и Codex.

При установке легко ошибиться в двух местах.

  • Хук должен стоять на всех инструментах, которые умеют читать файлы. В настройках Claude Code это поле matcher со списком инструментов. На Windows агент работает с командной строкой через PowerShell, а не через Bash, и если в списке есть только Bash, то cat .env будет заблокирован, а Get-Content .env пройдёт. Ещё один инструмент, о котором забывают, — Grep: он выводит найденные строки, то есть тоже читает файл. Наш список: Read|Edit|Write|Grep|Bash|PowerShell.
  • Убедитесь, что хук действительно блокирует. На Windows Claude Code может запускать хуки через PowerShell, а PowerShell превращает код выхода 2 в 1. Код 1 Claude Code считает ошибкой хука и действие не останавливает. Мы думали, что защищены, пока не попросили агента прочитать .env и не увидели, что он прочитал.

Проверять хук нужно именно так — руками и настоящим агентом. Попросите его прочитать файл из .secrets и показать .env. Оба запроса должны закончиться отказом. Мы на этом поймали и собственную ошибку: хук смотрел только на имя файла в конце пути. Папка .secrets целиком была закрыта, а cat .secrets/token.txt проходил, потому что token.txt — безобидное имя. Эта версия стояла и в этом блоге, пока мы готовили статью.

Если пишете свой хук, проверьте его ещё на нескольких случаях, которые нашло ревью нашего:

  • разрешённая команда, перевод строки и вторая команда, например cat .env;
  • путь, который только похож на путь доверенного скрипта, вроде evil.agents/skills/…/handoff.sh;
  • поиск через Grep с полем glob: .env.

Шаг 4. Кладите токены через буфер обмена, а не через чат

Остаётся вопрос, как токен из панели Cloudflare попадёт в файл. Открыть файл и вставить туда токен руками — нормальный вариант. Но если вы и так работаете в окне агента, есть способ удобнее: скопируйте токен и выполните в строке ввода агента команду из того же репозитория (на macOS и Linux вместо py -3 — python3):

! py -3 $HOME/.agents/skills/secret-handoff/handoff.py put cloudflare-token-blog --clipboard

В переписку попадёт только эта строка, а в ней лишь имя cloudflare-token-blog. Скрипт возьмёт токен из буфера обмена, сохранит его в закрытую папку в вашем домашнем каталоге и очистит буфер, если там всё ещё лежит этот же токен. В ответе будет имя и длина, но не значение. Скрипт предупредит и о том, что копия могла остаться в истории буфера: Win+V на Windows, история буфера на macOS, менеджер буфера на Linux. Её удалите сами. Потом скажите агенту, куда токен положить, и он перенесёт его в файл проекта командой take, тоже не видя значения.

Тот же способ выручает, когда ключ нужен в другом проекте. Например, в одном окне агент выпустил API-ключ, а пользоваться им будет агент в соседнем проекте. Переслать ключ сообщением — значит снова оставить его в переписке. Вместо этого первый агент кладёт ключ в ту же закрытую папку, а второй забирает его к себе:

handoff.sh put  <name> --from <file> [--line N | --key VAR] [--remove-source]
handoff.sh take <name> --into <secret file> [--key VAR]
handoff.sh drop <name>
handoff.sh list

В сообщении между проектами остаётся только имя ключа и для чего он. take записывает ключ только в файл, который охраняет хук, а с --remove-source у отправителя не остаётся копии. Посылку, которую никто не заберёт, удаляет drop, не открывая её. Хук разрешает агенту ровно один вызов этого скрипта за раз и не даёт дописать к нему вторую команду. Чтобы хук этот скрипт узнал, клонируйте репозиторий в то место, которое указано в README:

git clone https://github.com/investblog/secret-handoff ~/.agents/skills/secret-handoff

Чем эта защита слаба

Всё это — ремень безопасности на случай ошибки агента. Агента, который задался целью добраться до ключа, он не остановит. Хук видит текст команды, поэтому не заметит путь, который собирается на ходу (.sec''rets, маска, переменная). Он не поможет, если сам токен уже оказался в тексте запроса, — для этого нужен второй рубеж, проверка коммитов на секреты. Хуку нужен Python: если Python не найден, хук пропускает всё, чтобы не заблокировать агента целиком. А в Codex хук читает весь текст патча, и правку документа, где просто упоминается .env, он тоже отклонит — такую правку придётся сделать другим инструментом.

И про !: строка команды всегда попадает в переписку. Буфер обмена спасает значение, но историю команд и историю буфера чистите сами.

Если вы сами делаете API для агентов

Пока речь шла о том, кто видит ключ. Если же вы делаете сервис, который будут вызывать агенты, например MCP-сервер на Workers, можно сделать так, чтобы утёкший ключ мало что давал. В открытом clx это устроено так: выпустить ключ можно только из аккаунта, куда вошёл человек, поэтому ключом нельзя выпустить другой ключ. У каждого ключа свои права и, по желанию, список разрешённых аккаунтов Cloudflare и IP-адресов. Сервер хранит только хэш и показывает ключ один раз. А скрипт, который выпускает ключ, отзывает его сам, если ответ сервера потерялся или ключ не удалось сохранить, так что «потерянных» рабочих ключей не остаётся.

Когда нужны clx или 301.st

Если аккаунт Cloudflare ваш и агент один, хватит узкого токена, скрипта и хука. Всё это бесплатно.

clx считает визиты, клики по коротким ссылкам и сканы QR-кодов на ваших сайтах — воркером и базой D1, которые ставит в ваш аккаунт Cloudflare. Его API-ключи устроены как раз так, как описано выше, и их можно спокойно отдавать агенту.

301.st делает то же самое с самим токеном Cloudflare. Вы создаёте временный токен с правом создавать токены. 301.st один раз использует его, чтобы выпустить свой рабочий токен: с фиксированным набором прав, без права создавать токены, со сроком действия пять лет. Потом удаляет временный токен, а рабочий хранит зашифрованным. Если Cloudflare не даст удалить временный токен, 301.st запишет это в лог, и токен останется в вашей панели — удалите его вручную. Дальше 301.st ведёт редиректы, правила трафика и зоны всего вашего портфеля этим рабочим токеном.
